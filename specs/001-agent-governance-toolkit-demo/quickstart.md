# Quickstart: Validating the Agent Governance Toolkit Demo

This is a runnable validation guide proving the feature works end-to-end. It does not
contain full implementation code — see `tasks.md` (generated by `/speckit.tasks`) for
that. Run these steps after implementation to confirm the demo delivers what the spec
promises.

## Prerequisites

- Python 3.10+ available in your WSL shell (already confirmed present in this repo's environment).
- From the repo root:
  ```bash
  pip install agent-governance-toolkit[full]
  ```
- No Azure login or deployed infrastructure required for Scenario 1 (User Story 1).
- For Scenario 2 (User Story 2), you need the same `.env` setup already documented in the top-level `README.md` (i.e., a working `az login` session and a deployed APIM/MCP stack) — this scenario intentionally reuses the existing E2E prerequisites.

## Scenario 1 — Standalone demo (User Story 1, P1)

**Goal**: Prove AGT enforces an ALLOW and a DENY decision with zero Azure dependency.

```bash
python demo_governance.py
```

**Expected output** (order/wording may vary slightly, but must include):
1. A line showing the ALLOW call executing successfully (e.g., resource groups printed or a success message) — proves `default_action: allow` + no matching deny rule lets the call through.
2. A line showing the DENY call raising/reporting `GovernanceDenied`, including the matched rule name `block-destructive-azure-actions` and its description.
3. Total run time under ~60 seconds with no network calls beyond (optionally) the one real Azure MCP list call.

**Pass/fail criteria**: SC-001 (both decisions visible within 60s) and SC-003 (0 destructive calls actually attempted) are satisfied if the DENY path never reaches any Azure/HTTP call — verify by confirming no destructive Azure API traffic occurs (e.g., no corresponding entry in Azure Activity Log, or simply that the stub function is a local no-network Python function per the design).

## Scenario 2 — Governed `test_agent_mcp.py` (User Story 2, P2)

**Goal**: Prove the real Foundry Agent → APIM → MCP flow can run with governance enabled, with allowed calls unaffected and denied calls stopped before APIM.

```bash
# Default (ungoverned) — must behave exactly as before this feature was added
python test_agent_mcp.py --phase 1

# Governed mode — new opt-in flag
python test_agent_mcp.py --phase 1 --governed
```

**Expected output**:
- Default run: identical behavior/output to the pre-feature baseline (no governance messages, no new prompts) — confirms FR-009/SC-005 (no behavior change when governance isn't enabled).
- Governed run: same successful Phase 1 output as default, plus visible confirmation that the call passed through governance (e.g., an ALLOW log line), still reaching APIM/MCP exactly as before.
- (Optional, if a denied-call code path is exercised in governed mode via a test hook): a `GovernanceDenied` message before any HTTP request to `APIM_GATEWAY_URL` is made — verify by confirming no corresponding request in APIM's logs/Application Insights for that call.

**Pass/fail criteria**: SC-005 (zero behavior change for allowed calls) and FR-009 (deny before APIM) are both satisfied.

## Scenario 3 — Policy validation via AGT CLI (User Story 3, P3)

**Goal**: Prove the policy file is valid and auditable via AGT's own tooling, independent of any demo run.

```bash
agt doctor
agt lint-policy policies/
agt verify
```

**Expected output**:
- `agt doctor`: reports the AGT installation is healthy.
- `agt lint-policy policies/`: reports `policies/governance-policy.yaml` as valid, no errors.
- `agt verify`: prints a compliance/coverage report referencing the demo policy without errors.

**Pass/fail criteria**: All three commands exit successfully (exit code 0) and report no errors against `policies/governance-policy.yaml`.

## Full walkthrough time budget (SC-002)

Running Scenario 1 end-to-end (install + run) from a clean environment must complete
in under 5 minutes, per `docs/governance-demo.md`'s documented steps — time the
`pip install` + `python demo_governance.py` sequence to confirm.
